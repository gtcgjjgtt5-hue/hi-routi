# 💘 사랑의 스튜디오 (love-studio)

1990년대 감성 소개팅 쇼를 그대로 옮긴 모바일 웹앱입니다.
남자 13명 · 여자 12명이 **번호와 출생연도로만** 만나고, 사회자(MC)가 진행을 맡습니다.

> 2026-11-26 막차로 **남자 11~13호 · 여자 11~12호**가 추가됐습니다. 기존 1~10호의 번호·출생연도·PIN은 그대로라서, 먼저 보낸 초대 링크도 계속 쓸 수 있습니다.

- 참가자: 익명 라운지 · 사회자 1:1 · 사랑의 작대기(1지망/2지망/최종) · 매칭 1:1 비밀방
- 사회자: 단계 진행(대기 → 1부 → 2부 → 3부 → 발표) · 전체 방송 · 명단/초대 링크 · 투표 현황 · 결과 공개

> 이 문서는 **운영자(사회자)만** 보는 문서입니다. 참가자에게는 초대 링크만 보내 주세요.

## 2. 참가자 초대하는 법 (가장 중요)

1. 사회자로 입장 → 아래 **명단** 탭
2. 각 줄의 `링크` 버튼 = 그 사람 전용 초대 링크 복사 (`.../?code=m3-9157`)
3. 스레드 DM으로 한 사람당 하나씩 보내면 끝. `링크 전체 복사`로 25명치를 한 번에 복사할 수도 있어요.
4. `아이디 일괄 입력`을 누르고 아래 형식으로 붙여넣으면, 사회자 화면에만 스레드 아이디가 표시됩니다.

```
남자 1호 @example_1
남자 2호 @example_2
...
여자 12호 @example_25
```

> 예시는 전부 가짜 아이디(`@example_1` …)입니다. 실제 아이디는 여기에 적지 말고, 앱 화면에서만 쓰세요.

> **아이디는 앱 코드에 넣지 않았습니다.** 공개 저장소에 올라가면 참가자 신상이 그대로 노출되기 때문에,
> 사회자 브라우저(localStorage)에만 저장됩니다. 다른 기기에서 사회자로 들어가면 다시 입력해야 합니다.

### 개인 PIN

개인 PIN은 앱의 `명단` 탭에서 `링크`/`PIN` 버튼으로 바로 복사할 수 있습니다. (25명 PIN 표는 보안상 README에 적지 않았습니다. 
PIN은 `js/data.js`에 있습니다.)

바꾸고 싶으면 `js/data.js`의 `pin` 값만 고치고 다시 올리면 됩니다. (초대 링크도 자동으로 바뀝니다.)

> ⚠️ **PIN은 실수 방지용 잠금이에요.** 이 앱의 코드는 공개되어 있어서, 소스를 열면 PIN을 볼 수 있습니다.
> 서로 아는 사이의 이벤트를 전제로 만들었습니다. 진짜 비밀이 필요한 정보(연락처·실명·계좌)는 앱에 넣지 마세요.

## 3. 사회자 진행 순서 (MC 가이드)

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| 대기중 | 진행 | 참가자 입장 확인, `📢 바로 보내기`로 환영 방송 |
| 1부 · 자기소개 & 단체톡 | 진행 → `다음 단계` | 라운지에서 자기소개, 질문은 1:1로 받기 |
| 2부 · 첫인상 선택 | `다음 단계` | 참가자 화면에 작대기(1지망/2지망)가 열림. 투표 탭에서 제출 현황 확인 |
| 3부 · 최종 사랑의 작대기 | `다음 단계` | 최종 선택 칸이 추가로 열림 |
| 결과 발표 | `💘 결과 공개 & 매칭방 열기` | 상호 선택 커플의 1:1 방이 열리고, 모두에게 관계도가 공개됨 |

- 단계는 상단 스텝(대기/1부/2부/3부/발표)을 눌러 바로 이동할 수도 있습니다. 이동할 때마다 라운지에 시스템 안내가 뜹니다.
- 발표 전까지 참가자 화면에는 **다른 사람의 선택이 보이지 않습니다.** (사회자 투표 탭에서는 미리 보임)
- `전체 대화·투표 초기화`는 되돌릴 수 없습니다. 리허설 후 실제 시작 전에 한 번 눌러 초기화하세요.

### 결과 공개 규칙

- 서로의 선택(1지망·2지망·최종 중 하나라도)이 맞물리면 **매칭 성사** → 두 사람만의 1:1 비밀방이 열립니다.
- 우선순위: 최종 > 1지망 > 2지망. 한 사람이 여러 명을 골랐어도, 상대가 나를 골랐으면 매칭입니다.
- 매칭이 없어도 괜찮습니다. 참가자에게는 "사회자에게 마음을 전해 보세요" 안내가 나옵니다.

## 4. Firebase 연결 상태 (2026-11-26 연결 완료)

**연결됨**: 프로젝트 `love-studio-6bin-4b51b`, RTDB 리전 `asia-southeast1`, 규칙은 아래 `.read/.write: true`(테스트 모드)로 열려 있습니다.
확인한 것: LIVE 배지 · 사회자 PIN 입장 · 참가자 초대링크 입장 · 라운지/공지/1:1/투표 읽기·쓰기 실시간 반영.

> 다른 프로젝트로 옮기거나 체험 모드로 되돌릴 때만 아래 순서가 필요합니다.

체험 모드는 **한 기기 안에서만** 동작합니다. 25명이 각자 폰으로 접속하려면 Firebase Realtime Database를 연결하세요. (무료 Spark 요금제로 충분합니다)

1. https://console.firebase.google.com → **프로젝트 추가** (이름 예: `love-studio`)
2. 왼쪽 메뉴 **빌드 → Realtime Database → 데이터베이스 만들기**
   - 위치: `asia-southeast1` (한국에서 가장 가깝습니다)
   - 보안 규칙: **테스트 모드**로 시작 (아래 5번에서 규칙을 정리)
3. 프로젝트 설정(⚙️) → **내 앱** → 웹 앱 추가(`</>`) → 앱 등록
4. 표시되는 `firebaseConfig` 값을 복사해 `js/config.js`의 `window.FIREBASE_CONFIG`에 붙여넣기
5. **Realtime Database → 규칙** 탭에 아래를 붙여넣고 게시

```json
{
  "rules": {
    "studio": {
      ".read": true,
      ".write": true
    }
  }
}
```

6. 커밋 & 푸시 → GitHub Pages가 자동 반영 (1~2분)
7. 앱 첫 화면 배지가 `체험` → `LIVE`로 바뀌면 연결 성공

```js
// js/config.js 예시
window.FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "love-studio-1234.firebaseapp.com",
  databaseURL: "https://love-studio-1234-default-rtdb.asia-southeast1.firebasedatabase.app",
  projectId: "love-studio-1234",
  storageBucket: "love-studio-1234.appspot.com",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef1234567890"
};
```

### 저장 구조

```
studio/
  status/{round}                   현재 단계 (waiting·r1·r2·r3·reveal)
  announcements/{id}               사회자 공지
  lounge/{id}                      전체 익명 라운지 메시지
  dm/{참가자id}/{id}                참가자 ↔ 사회자 1:1
  votes/{참가자id}                  {first, second, final, at}
  results                          발표 시점에 계산된 커플·선택 (공개용)
  rooms/{남자id__여자id}            매칭방
  roomChat/{방id}/{id}              매칭 1:1 대화
  presence/{참가자id}               접속 표시 (25초마다 갱신)
```

### 보안에 대해 (솔직한 안내)

- 4자리 PIN은 **실수 방지용 잠금**입니다. 앱 소스가 공개되어 있어 코드를 열면 PIN을 볼 수 있습니다.
  서로 아는 사이의 이벤트를 전제로 만들었으니, 민감한 개인정보(연락처·실명·계좌 등)는 앱에 넣지 마세요.
- 위 규칙(`.read/.write: true`)은 누구나 데이터를 읽고 쓸 수 있는 상태입니다. 이벤트가 끝나면
  `.write`를 `false`로 바꿔 잠그거나 데이터베이스를 비워 두세요.
- 더 단단하게 쓰려면 Firebase **익명 인증**을 켜고, 규칙에서 `auth != null`을 요구하는 방식으로 확장할 수 있습니다.

## 6. 자주 막히는 곳

- **참가자에게 보낸 링크가 안 열려요** → 링크가 `?code=m3-9157` 형태인지 확인. 주소 끝에 슬래시가 빠져도 동작합니다.
- **비밀번호가 달라요** → 사회자 화면의 `명단` 탭에서 해당 참가자의 `PIN`을 복사해 확인하세요.
- **사회자 화면인데 참가자처럼 보여요** → `나가기` 후 다시 `🎤 사회자로 입장`.
- **메시지가 안 보여요** → 두 사람이 같은 주소(임시 주소 vs 최종 주소)로 들어왔는지 확인. 주소가 다르면 저장소도 다릅니다.
- **발표 후 방을 다시 열고 싶어요** → 이미 열린 매칭방은 `투표` 탭에서 `방 열림`으로 표시됩니다. 참가자는 1:1 탭에서 들어갑니다.
- **처음부터 다시 리허설** → 진행 탭 → `전체 대화·투표 초기화`.
